# Memory Bank — ведение

Читай, только когда правишь `memory-bank/**`. Маршрутизация — `index.md`, правила чекпоинта — `activeContextRules.md`.

## Бюджеты

| Файл                   | Целевой бюджет |
| :--------------------- | -------------: |
| index.md               |    950 токенов |
| projectbrief.md        |  1 500 токенов |
| techContext.md         |  1 500 токенов |
| systemPatterns.md      |  1 500 токенов |
| defects.md             |  1 000 токенов |
| local/activeContext.md |    800 токенов |

Инструкции (читаются по требованию, в бюджет задачи не входят): `maintenance.md` ≤ 1 500 токенов,
`activeContextRules.md` ≤ 400.

- Бюджеты мягкие: превышение — повод пересмотреть структуру и убрать дубли, но не удалять знания, которых нет в коде
- Агрегатного лимита на Memory Bank нет; бюджет задачи и сценарии загрузки — `index.md`
- Оценка — токенизатором активной модели, если он доступен; иначе верхняя оценка `кириллица/2 + остальное/4` (для
  современных токенизаторов завышает на 10–30 %, бюджет считается выполненным с запасом)
- Новый документ — бюджет по содержанию и частоте загрузки, строка в таблице выше, а не «сколько получилось»
- Строки и символы не лимитируются: единственная метрика — токены

## Правила

- Один факт — в одном файле, в остальных ссылка («см. `techContext.md`»); запись = утверждение + путь к источнику, без
  кода, логов и пересказа `schema.ts` или конфигов
- Документируй намерение, причину, отвергнутые варианты, ограничения и контракты — то, чего не выводится из кода;
  хронология — `git log`, решения — `systemPatterns.md`, открытые долги — `defects.md`; состояние проекта в документах не
  хранится
- Не документируй пороги, версии и числа покрытия
- Дефект или долг — строка `D-NN` в `defects.md` с путём к коду; ID не перенумеровывается, закрытый переезжает в
  «Закрытые», а не удаляется
- Запись в `defects.md` — без дат: время и автор — `git log`; даты живут только в шапке чекпоинта
  (`activeContextRules.md`)
- Документ противоречит коду — исправь документ в той же задаче; документ противоречит документу — дефект ревью
- Новый документ — строка в таблице `index.md` и целевой бюджет в таблице выше; удалённый — его строки убрать
- Изменил структуру банка — обнови `index.md`, этот файл, `activeContextRules.md` и `AGENTS.md` §«Memory Bank»
- Правила ведения и чекпоинта не дублируй в `index.md` и `AGENTS.md`: там только ссылка на файл правил и бюджет загрузки
  задачи, он нужен в каждой задаче

## Проверка перед сдачей

- Дублей нет — пусто: каждый факт живёт в одном файле, инструкции исключены (в них сами шаблоны):

  ```bash
  grep -rnoE '200 мс|resetWeatherCache|#c2185b|WORD_SEPARATORS' memory-bank/*.md \
    | grep -vE 'index|maintenance|activeContextRules' | cut -d: -f3 | sort | uniq -d
  ```

- Объём документов в пределах целевых бюджетов; превышение — зафиксируй причину, а не молча оставляй:

  ```bash
  node -e 'const fs=require("fs");for(const f of process.argv.slice(1)){const s=fs.readFileSync(f,"utf8");const c=(s.match(/[\u0400-\u04FF]/g)||[]).length;console.log(f,Math.round(c/2+(s.length-c)/4))}' memory-bank/*.md memory-bank/local/activeContext.md
  ```

- `npx prettier --check memory-bank/*.md` зелёный
- Пути и имена документов существуют (`ls memory-bank/`, исключение — `AGENTS.md`), чекпоинт обновлён в конце последней
  задачи и содержит всю сессию, шапка совпала с `git rev-parse`; удалённый документ не упомянут в правилах и `AGENTS.md`
