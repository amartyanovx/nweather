# Memory Bank — ведение

Читай, только когда правишь `memory-bank/**`. Маршрутизация — `index.md`, правила чекпоинта — `activeContextRules.md`.

## Бюджеты

| Файл                   | Целевой бюджет |
| :--------------------- | -------------: |
| index.md               |    950 токенов |
| projectbrief.md        |  1 500 токенов |
| techContext.md         |  2 000 токенов |
| systemPatterns.md      |  1 500 токенов |
| local/activeContext.md |    800 токенов |

Инструкции (читаются по требованию, в бюджет задачи не входят): `maintenance.md` ≤ 1 500 токенов,
`activeContextRules.md` ≤ 400.

- Бюджеты — мягкие ориентиры для структуры, а не лимиты: заметно больше целевого — повод убрать дубли и пересказ кода, но
  не удалять знания, которых нет в коде
- Отдельный замер токенов не обязателен: бюджеты в таблице — в токенах, `wc -m` — сравнение объёмов между документами и
  с прошлой версией файла, а не перевод в токены
- `techContext.md` шире прочих: в нём стек, Next.js-соглашения, команды, тесты и данные, вынесенные из Harness-правил
- Агрегатного лимита на Memory Bank нет; бюджет задачи и сценарии загрузки — `index.md`
- Новый документ — бюджет по содержанию и частоте загрузки, строка в таблице выше, а не «сколько получилось»

## Правила

- Один факт — в одном файле, в остальных ссылка («см. `techContext.md`»); запись = утверждение + путь к источнику, без
  кода, логов и пересказа `schema.ts` или конфигов
- Документируй намерение, причину, отвергнутые варианты, ограничения и контракты — то, чего не выводится из кода;
  хронология — `git log`, решения — `systemPatterns.md`; состояние проекта в документах не хранится
- Не документируй пороги, версии и числа покрытия
- Документ противоречит коду — исправь документ в той же задаче; документ противоречит документу — дефект ревью
- Новый документ — строка в таблице `index.md` и целевой бюджет в таблице выше; удалённый — его строки убрать
- Изменил структуру банка — обнови `index.md`, этот файл, `activeContextRules.md` и `harness/main-session.md`
  §«Memory Bank»
- Правила ведения и чекпоинта не дублируй в `index.md` и `harness/main-session.md`: там только ссылка на файл правил,
  границы банка и бюджет загрузки задачи, он нужен в каждой задаче

## Проверка перед сдачей

- Каждый факт — в одном файле. Возьми характерные факты задачи (путь, имя функции, число) и проверь, что в остальных
  документах на них ссылка, а не копия: инструкции (`index.md`, `maintenance.md`, `activeContextRules.md`) исключены — в них
  сами шаблоны

  ```bash
  grep -rn '<характерный факт>' memory-bank/*.md | grep -vE 'index|maintenance|activeContextRules'
  ```

- Объём — `wc -m memory-bank/*.md memory-bank/local/activeContext.md`: сравнивай документ с соседними и с его прошлой
  версией (`git diff --stat`); заметно больший — зафиксируй причину, а не оставляй молча
- `npx prettier --check memory-bank/*.md` зелёный
- Пути и имена документов существуют (`ls memory-bank/`, исключение — `AGENTS.md`), чекпоинт обновлён в конце последней
  задачи и содержит всю сессию, шапка совпала с `git rev-parse`; удалённый документ не упомянут в правилах Harness
