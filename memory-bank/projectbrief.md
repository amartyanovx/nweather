# Project Brief: nweather

## Назначение

Демонстрационное приложение погоды на Next.js App Router и TypeScript (версии — `package.json`). Показывает App Router
на одном полном сценарии — выбор города → недельный прогноз → переключение дней, с Server Components по умолчанию и
минимальным клиентским островом.

Данные вымышленные (mock-seed, 7 городов × 7 дней); схема — `src/lib/schema.ts`, фактическое состояние — `progress.md`.
Переход на реальный Weather API — в планах, см. `progress.md`.

## Границы

- В скоупе: выбор города, недельный прогноз, табы по дням, состояния загрузки и ошибки с повтором.
- Вне скоупа: авторизация, пользовательские настройки, геолокация, реальный провайдер погоды, адаптив сверх простой
  центрированной вёрстки.

## Инварианты

- Строгая типизация без `any`; Server Components по умолчанию.
- Источник данных — SQLite `dev.db` через Drizzle; API отдаёт `WeatherDay[]` фиксированной длины (инвариант порядка
  дней — `systemPatterns.md`).
- Отсутствующая метрика не подменяется нулём: в интерфейсе показывается `—`.

## Сценарий и UX-правила

- Экран: заголовок «Nweather» → `<select>` с городами → табы дней (активный подсвечен) → карточка с максимальной и
  минимальной температурой, осадками и давлением.
- По умолчанию активен текущий день недели (расчёт индекса — `src/app/page.tsx`).
- До выбора города прогноза нет — виден только select. Загрузка — skeleton-заглушки вместо select и карточки
  прогноза, ошибка — «Не удалось загрузить погоду» с кнопкой «Повторить» (повторный запрос через `mutate` из SWR).
- Минимализм: одна колонка, числа моноширинным шрифтом; кэш SWR исключает повторные запросы.

## Точки входа

Стек — `package.json`, пояснения — `techContext.md`; API — `src/app/api/weather/route.ts`; хуки — `src/hooks/`; границы
Server/Client Components — `systemPatterns.md`.
