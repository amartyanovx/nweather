# Memory Bank — индекс

Открывать первым. Здесь только маршрутизация: что читать под задачу. Факты — в коде и конфигах, решения — в документах.

## Документы

| Файл                   | Только то, чего нет в коде                                               | Читать когда                           | Бюджет     |
| :--------------------- | :----------------------------------------------------------------------- | :------------------------------------- | :--------- |
| projectbrief.md        | Зачем проект, границы, инварианты, сценарий и UX-правила                 | Новые функции, оценка объёма           | ≤ 45 строк |
| techContext.md         | Контракт API, неочевидные настройки, ловушки окружения                   | Конфиги, зависимости, контракты        | ≤ 55 строк |
| systemPatterns.md      | Решения и их причины, поток данных, ловушки БД                           | Проектирование, рефакторинг            | ≤ 60 строк |
| local/activeContext.md | Снимок текущей работы вне git: очищается на новой сессии или смене ветки | Перезапуск сессии, своя текущая работа | ≤ 25 строк |
| progress.md            | Состояние, долги, известные дефекты                                      | Планирование, приёмка                  | ≤ 40 строк |

Всего ≤ 15 000 символов, `index.md` ≤ 65 строк. Бюджет превышен — не дописывай текст, а удаляй дубли: то, что
выводится из кода и конфигов (версии, пороги, схема, состав файлов), в документах не хранится, только ссылка.

## Маршрутизация

| Задача                        | Читать                                                                 |
| :---------------------------- | :--------------------------------------------------------------------- |
| Новая функциональность        | projectbrief → решения в systemPatterns                                |
| Исправление ошибки            | поток данных в systemPatterns, дефекты в progress                      |
| Рефакторинг                   | systemPatterns; techContext — если конфиги или зависимости             |
| Конфигурация и инфраструктура | techContext                                                            |
| Продолжение работы            | `local/activeContext.md` (если шапка совпала с веткой/HEAD) → progress |

Не читай весь Memory Bank. Один документ на задачу; второй — только если на него есть ссылка.

## Источники истины (не переписывать сюда)

| Факт                                          | Где смотреть                                                   |
| :-------------------------------------------- | :------------------------------------------------------------- |
| Версии, скрипты, зависимости                  | `package.json`, `package-lock.json`                            |
| Пороги, globs, таймауты, окружения проверок   | `jest.config.ts`, `.stryker.config.js`, `playwright.config.ts` |
| Схема БД, подключение, seed                   | `src/lib/schema.ts`, `src/lib/db.ts`, `src/lib/seed.ts`        |
| Состав файлов и каталогов                     | `src/`, `__tests__/`, `tests/`                                 |
| Правила кода, команды, лимиты, форматирование | `AGENTS.md`                                                    |
| Покрытие, счётчики тестов, оценка мутантов    | вывод `npm test`, `npm run mutate`, `npm run e2e`              |

## Правила ведения

- Один факт — в одном файле, в остальных ссылка («см. `techContext.md`»), а не повтор; запись = утверждение + путь к
  источнику, без кода, логов и пересказа `schema.ts` или конфигов. Документируй только намерение, решение и причину,
  отвергнутые варианты, ограничения и контракты, не выводимые из кода.
- Не документируй пороги, версии и числа покрытия; состояние — в `progress.md`, хронология — в `git log`, решения — в
  `systemPatterns.md`.
- `local/activeContext.md` — снимок текущей работы, не журнал: содержимое очищается только при старте новой сессии
  или смене ветки, в остальных случаях не очищается и не удаляется; по ходу работы файл заполняется и актуализируется
  под текущее состояние задачи.
- Шапка `[hh:mm][dd-MM-yy] · ветка · HEAD · файлы из git status`, секции Цель/Шаги/Дальше/Дефекты; шапка не совпала с
  `git rev-parse` (другая ветка или HEAD) — файл черновик, состояние проекта читать в `progress.md`.
- Дефект или находка — одна строка в `progress.md`, раздел «Известные дефекты», со статусом и путём к коду.
- Новая запись — `[hh:mm][dd-MM-yy]` в заголовке `progress.md` и в шапке чекпоинта.
- Документ противоречит коду — исправь документ в той же задаче; документ противоречит документу — дефект ревью.
- Новый документ — строка в таблицах выше и бюджет; удалённый — его строки убрать.
- Изменил структуру Memory Bank — обнови `AGENTS.md`, раздел «Memory Bank».

## Проверка перед сдачей

- Нет дублей факта (`rg 'dev.db|Stryker|perTest|weatherMock' memory-bank/`), бюджеты и лимит символов соблюдены
  (`wc -c memory-bank/*.md`).
- Пути существуют, даты на месте, `npx prettier --check memory-bank/*.md` зелёный.
- Чекпоинт отражает текущее состояние работы сессии, без содержимого прошлых сессий.
