# Memory Bank — индекс

Здесь маршрутизация по задачам, правила использования документов и когда подключать файлы правил. Факты —
в коде и конфигах, решения — в документах.

## Документы

| Файл                   | Только то, чего нет в коде                                          |
| :--------------------- | :------------------------------------------------------------------ |
| projectbrief.md        | Зачем проект, границы, инварианты, UX-правила                       |
| techContext.md         | Стек, технические соглашения, команды, тесты, контракт API, ловушки |
| systemPatterns.md      | Решения и причины, поток данных, ловушки БД                         |
| local/activeContext.md | Снимок текущей сессии вне git                                       |

## Маршрутизация

| Задача                        | Читать                                                            |
| :---------------------------- | :---------------------------------------------------------------- |
| Новая функциональность        | projectbrief → решения в systemPatterns                           |
| Исправление ошибки            | поток данных в systemPatterns, статус — в Jira                    |
| Рефакторинг                   | systemPatterns; techContext — если конфиги, зависимости или тесты |
| Конфигурация и инфраструктура | techContext                                                       |
| Сбой или сжатие контекста     | `local/activeContext.md` (шапка совпала с веткой/HEAD)            |

## Дефекты и долг

Дефекты, технический долг и их статусы ведутся в Jira (пока не подключено). Memory Bank хранит только долгоживущие
технические знания, не дублируя бэклог.

## Правила использования

- Один документ на задачу, второй — только по ссылке из него; весь банк не читай. Бюджет загрузки — ≤ 3 000 токенов,
  комплексная задача — до 6 000
- Точечная правка кода без смены подхода документов банка не требует: достаточно `AGENTS.md`; `techContext.md` открывай,
  только когда нужен его раздел
- Правишь `memory-bank/**` — подключай `maintenance.md` (ведение, бюджеты, проверка перед сдачей); пишешь чекпоинт
  `local/activeContext.md` — `activeContextRules.md` в конце каждой задачи (чекпоинт хранит всю сессию). Оба файла
  читаются по требованию и в бюджет задачи не входят
- Новые правила ведения memory bank добавляй в `maintenance.md` или `activeContextRules.md`; в `index.md` — только
  маршрутизация и границы банка, в `AGENTS.md` и `.clinerules/core.md` — ссылки
