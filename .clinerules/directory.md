# Рабочая директория

Тебе разрешено работать ТОЛЬКО с файлами внутри текущей директории проекта.
Никогда не ищи файлы за пределом текущей директории проекта.
Никогда не используй команды терминала для выхода за пределы корня проекта (например, избегайте `cd ..`, `ls /`, доступ к `~/.` и т.д.).
Если нужно вызвать глобальную утилиту, делай это без изменения рабочей директории.
Используй файловые инструменты Cline для изучения проекта. Не используй терминал для операций с файлами, если для этих операций доступны инструменты Cline.
При выполнении команд в терминале используй синтаксис Bash. Перед завершением задачи останавливай запущенные фоновые процессы (dev-сервер, `npm start`, E2E) и не оставляй занятыми порты проекта; в Bash-совместимой оболочке для этого используй `kill`.
Использовать cmd и powershell полностью запрещено без специального разрешения пользователя. Если задача объективно требует cmd или PowerShell (например, нужная утилита доступна только там), остановись и запроси разрешение, не обходи правило через другие оболочки.
Никогда не перенаправляй вывод команд в nul и не создавай временные файлы с именем nul. Используй корректный синтаксис для null-устройств или избегай перенаправления вывода. Не перенаправляй вывод в файлы проекта и не создавай файлы или каталоги в корне репозитория; промежуточные файлы храни только в системном временном каталоге.
Всегда считай корневую папку открытого проекта в VS Code основной рабочей директорией.
Перед поиском файлов сначала изучи структуру текущего workspace.
Приоритет путей: в вызовах инструментов и командах терминала используй абсолютные пути к файлам проекта; в тексте отчётов и документации — относительные от корня проекта.
