# Рабочая директория

## Территория и оболочка

- Работай только внутри корня открытого проекта (он же корень VS Code): без `cd ..`, `ls /`, `~/.`.
  Глобальные утилиты вызывай без смены каталога
- Оболочка: Windows — Bash/Git Bash; `cmd` и PowerShell запрещены, если задача объективно требует их — остановись и
  спроси разрешение, не обходя правило другими оболочками. Прочие ОС — доступная оболочка и соответствующие ей команды

## Файлы и пути

- Для операций с файлами используй инструменты Cline/VS Code, а не терминал: терминалу оставь то, что он делает
  лучше — подсчёты, списки путей, версии и прогоны проверок
- Никаких `nul` и временных файлов в проекте: промежуточные файлы — только в системном temp; вывод не перенаправляй
  в файлы проекта и в корень репозитория
- Пути: на Windows в инструментах и командах — абсолютные, на прочих ОС — от корня проекта; в отчётах и документации —
  всегда относительные от корня

## Разведка — дефолты, не запреты. Существенные отступления объясняй кратко

- Перед поиском файлов изучи структуру workspace: обычно она уже видна в environment_details, поэтому листинг повторно
  не запрашивай, если нужная папка видна и список не усечён
- Файл известен — читай его. Неизвестен — ищи по символу или строке, сузив путь и тип файла; ноль результатов — сними
  фильтр, расширь область
- Место правки известно — читай релевантные фрагменты; связи неясны — расширяй чтение по необходимости. Небольшой файл
  (сотни строк) не дроби: перед правкой должен быть виден точный текст изменяемого фрагмента
- Нашёл место правки — проверь использования и тесты, затем прекращай разведку
- Масштабируй разведку под задачу: багфикс не требует карты архитектуры

## Что не читать целиком

lock-файлы, generated, снапшоты, крупные фикстуры — кроме задач про них самих. Нужен факт (версия пакета, наличие
строки) — точечный поиск, а не чтение файла.

## Терминал

- Подсчёты, списки путей, версии — командой (`wc -l`, `npm ls`, `rg -c` или `grep -c`), не чтением файлов
- Разведочный листинг ограничивай: `head -n 50`, `git log -n 5 --oneline`, `git diff --stat`,
  `tree -L 2 -I 'node_modules|.git'`
- Тесты и сборка: вывод — в файл вне репо, код завершения фиксируй до конвейера, затем `grep` по ошибкам и `tail`.
  Полный лог должен оставаться доступным
- `2>/dev/null` — для тишины в шумных командах, чей вывод не нужен; лог проверок и сборки не выбрасывай

## Правки

- Существующие файлы — точечные изменения штатным инструментом редактирования, связанные правки — одной группой.
  Полная перезапись — только для нового файла или осознанной замены
- Не перечитывай неизменившийся файл из контекста. После своих правок, внешних изменений или сжатия контекста —
  перечитай нужный фрагмент

## Завершение задачи

- Гаси только процессы, запущенные в этой задаче (dev-сервер, `npm start`, E2E), через `kill` и не оставляй занятыми
  порты проекта
- Чужое состояние окружения не меняй: не трогай процессы, конфиги, данные и порты, которых не создавал в этой задаче
